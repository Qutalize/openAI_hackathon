# ディレクトリ構成と将来の拡張

## 固定する配置

モデル選定を `research/` に集約し、VSRと手話を分ける。各モデルの再現手順・実行補助・設定・所感を同じ場所に置く。
モデルごとにPython/PyTorch/CUDAの条件が異なっても、他の候補へ影響させず検証できるよう環境を分離する。

```text
.
├── README.md
├── AGENTS.md
├── docs/                         # 方針、構成、調査、チーム運用
├── research/
│   ├── templates/
│   │   └── REPORT_TEMPLATE.md     # 試運転と所感の記録様式
│   ├── vsr/
│   │   ├── README.md              # VSR比較表
│   │   ├── vallr/README.md
│   │   └── lipcoordnet/README.md
│   └── sign/
│       └── README.md              # 言語・候補選定。試す候補のフォルダを追加
└── data/
    └── README.md                 # 共通評価動画の保存方針
```

実際にモデルを動かす段階で、各 `<model_id>/` に必要なものだけ追加する：

| 配置 | 内容 | Git |
|---|---|---|
| `README.md` | 出所、状態、準備・実行手順、注意点 | 管理 |
| `reports/<date>-<run_id>.md` | 結果、所感、採用判断 | 匿名化した要約を管理 |
| `scripts/` | 取得/前処理/実行/評価の自作補助 | 管理 |
| `configs/` | 再現用設定。実データ・秘密を含めない | 管理 |
| 依存定義・lockfile | 実行を確認した依存バージョン | 管理 |
| `patches/` | 上流へ必要だった変更と適用手順 | 管理 |
| `upstream/` | revisionを固定した上流checkout | 対象外 |
| `.venv/` | モデル専用環境 | 対象外 |
| `weights/` | 重み、ランドマーク検出器等 | 対象外 |
| `outputs/` | 生出力、ログ、可視化、前処理キャッシュ | 対象外 |
共通入力は `data/vsr/` と `data/sign/` に置き、候補ごとに別の動画へ差し替えない。
これらの保存先はデータ取得時に作成する。入力ID・ハッシュ・撮影条件は実験記録に記載する。
モデル固有の前処理結果は各候補のoutputsへ置き、元データを上書きしない。
実行補助は作業ディレクトリの前提をREADMEへ明記し、他メンバーの絶対パスをハードコードしない。

## 将来インターフェースを追加する際の境界

- 必要になった時点で、ルートにアプリ用ディレクトリを追加する。今は空のUI/APIディレクトリを作らない。
- `research/vsr/` と `research/sign/` は移動・改名せず、過去の実験手順を維持する。
- モデル試運転は動画ファイルを入力するCLI等で単独実行できるようにする。UIやWebサーバーの起動を要求しない。
- アプリ側に呼出し用の処理を追加し、モデルの環境境界を保つ。HTTP等の方式はその時に決める。
- 実装共有が必要になったら独立モジュールとして切り出すことを検討するが、元の試運転入口は維持する。
- アプリ都合のroom_id、認証、字幕イベントなどをモデルの検証データへ持ち込まない。

これにより、インターフェースの追加がモデル選定のディレクトリ配置や記録に影響しない構成にする。
